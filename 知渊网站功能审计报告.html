一、总体结论

这是一个完成度很高的"演示型"单页应用：界面、导航、交互细节都做得相当完整，视觉与文案质量很高。但开箱即用时，真正"能跑"的功能有限——核心的 AI 对话、联网检索、云端持久化都依赖用户自行配置外部密钥 / 登录，且页面上大量"看起来有数据"的内容是写死的演示数据，并非真实功能产出。

一句话：展示层齐全，能力层待补齐 / 待说明。对访客来说，最需要的是在界面上把"这是演示 / 这里需要你配置"说清楚，否则极易误以为功能已可用。

三、需要重点说明 / 可能引起误解的地方

❌ 误导点 1：AI 面板的"多源回答"是假的。
首页 AI 顾问里那段"个人知识 / 网络资料 / AI 推断"的完整回答，是直接写死在 HTML 里的样例对话。真实使用时（无 key）只会弹出错误提示。访客极易误以为 AI 已能正常回答。
❌ 误导点 2："联网"功能不存在。
演示对话中的"本次联网 1 次，命中巨量算数 Q2 报告"纯属虚构。代码里没有任何联网搜索实现。
⚠️ 误导点 3：设置文案"AI 将以演示模式运行"不准确。
实际无 key 时并不会进入演示回答，而是直接报错。建议改为"未配置 Key 前 AI 无法使用，请先填写"。
⚠️ 误导点 4："云同步已开启 · 多设备实时共享"。
点击右上角同步徽标弹出的提示，在未登录 / 演示态下并不成立——数据此时只在本地浏览器。
⚠️ 误导点 5：满屏"数据"其实是演示数据。
"已连记 12 天""86 单元·12 SOP""本周 +128"等统计，以及知识中心全部条目，都是写死的样例。登录并真实录入后才会变成自己的数据。

四、建议在哪些位置补充"说明"

1. 首页顶部加一条演示横幅（最优先）
例如："当前为演示版本，展示的是示例数据。AI 对话与联网需在「设置」中填写你自己的 DeepSeek / 火山方舟 Key；登录后可开启云端同步保存你自己的内容。" 一句话消除绝大多数误解。
2. AI 顾问面板（未配置时）
把"AI 将以演示模式运行"改为明确指引："尚未配置 API Key，AI 暂不可用。点击右上角「AI 未配置」→ 填入 DeepSeek Key（对话）+ 火山方舟 Key/模型（向量检索）后即可使用。" 并给出两个官方申请链接（已在设置里有）。
3. 搜索框
二选一：① 接上真正的检索逻辑（对 records / 知识库做本地关键词过滤）；② 若暂不做，移除该框或标注"检索即将上线"，避免"有框不能用"的负面体验。
4. 知识中心 / 待整理箱空状态
当用户真实库为空时，显示"这是演示数据；登录并保存你的第一条记录后，这里会显示你的真实内容"，而不是一直展示别人的样例。
5. 同步徽标提示
未登录时提示改为"未登录：数据仅保存在本设备"；登录成功后再显示"云同步已开启"。
6. 后端数据表（若要真正落地）
当前 Supabase 仅 records 与 knowledge_entries 两张表且为空。若"项目 / SOP / 候选 / 每周整理"需要独立持久化，需补建对应表与 RLS 策略，或明确文档说明本版仅 records/knowledge_entries 入库。
